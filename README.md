# Каскад — портал каскадирования коммуникаций «Петрович»

Интерактивный прототип портала, на котором руководители заводят «паспорт инфоповода». Тип коммуникации
задаёт тональность и обязательные каналы, срок доведения портал считает сам — всё по Положению
о каскадировании. При запуске каскада руководители-адресаты получают задание о каскадировании, и у каждого
формируется личная повестка — все сообщения, которые нужно довести до команды, одним списком.
Пилотная структура — Дирекция по персоналу.

## Стек

React 18 · TypeScript (strict) · Vite · Tailwind CSS 4 · Zustand · Framer Motion · date-fns · lucide-react

Портал рассчитан на браузеры, которые поддерживает Tailwind CSS 4: Chrome и Edge 111+, Safari 16.4+, Firefox 128+.

## Команды

Нужен Node.js 20.19+ или 22.13+ (версия для nvm — в `.nvmrc`).

```bash
npm install
npm run dev           # дев-сервер на http://localhost:3000/kaskad-website/
npm run build         # проверка типов + production-сборка в dist/
npm run preview       # локальный просмотр сборки
npm run typecheck     # только проверка типов
npm run lint          # ESLint (typescript-eslint, react-hooks); предупреждения тоже валят проверку
npm run format        # Prettier (+ сортировка классов Tailwind)
npm run format:check  # проверка форматирования без изменений
```

## Публикация и автоматизация

- Сайт публикуется на GitHub Pages: <https://nanotheslayer.github.io/kaskad-website/>. Деплой запускает
  каждое слияние в `main` (`.github/workflows/deploy.yml`).
- Изменения попадают в `main` только через pull request с зелёным статусом «Проверки»
  (`.github/workflows/ci.yml`: typecheck, lint, format:check, build и `npm audit` продакшн-зависимостей).
  Прямой push, force-push и удаление `main` запрещены ruleset'ом репозитория.
- Dependabot раз в неделю открывает PR с обновлениями npm-пакетов и действий GitHub
  (`.github/dependabot.yml`); минорные и патч-версии приходят одним PR, мажорные — по отдельности.
  Алерты безопасности и сканирование секретов включены в настройках репозитория.
- Действия в workflow закреплены по SHA коммита с комментарием о версии, и настройки Actions требуют
  такого закрепления. Dependabot обновляет SHA и комментарий вместе.

## Структура `src/`

```
pages/            страницы (по одной на раздел меню)
layouts/          каркас страницы (сайдбар, шапка, заголовок) и граница ошибок страницы
components/
  ui/             базовые компоненты: Button, Card, Badge, Chip, Segmented, Stepper…
  navigation/     сайдбар, шапка, хлебные крошки, логотип
  communication/  карточка коммуникации, паспорт (drawer), каналы
  classification/ шаги формы паспорта и модель черновика (passportDraft.ts)
data/             справочники и демо-данные по Положению: типы, уровни, каналы, площадки, приоритеты, кризис, оргструктура
types/            доменные типы
utils/            чистая логика без React: правила каскада, задания и повестки, дерево оргструктуры, шкала таймлайна
store/            Zustand-стор: созданные пользователем коммуникации и подтверждения доведения (localStorage, с миграцией)
theme/            цвета из данных: типы коммуникаций, уровни, группы каналов, статусы, оценки
hooks/            общие хуки
routes.ts         разделы портала: путь, пункт меню, заголовок, иконка
```

## Соглашения

- Цвета — по брендбуку «Петровича»: жёлтый — фирменный фон и отметка текущего раздела, красный — действия
  и информация, которую нужно выделить, чёрный и графит — текст и структура. Остальной интерфейс нейтральный,
  а приглушённые цвета из `palette` только различают категории данных: типы, статусы, оценки.
- Цвета из данных — только через `palette` и `alpha()` из `theme/colors.ts`. Цвета для классов Tailwind
  описаны в блоке `@theme` в `src/index.css`.
- Свои глобальные стили — только внутри `@layer base` в `src/index.css`: в Tailwind 4 правило вне слоя сильнее
  любой утилиты и перебьёт классы на элементах.
- Справочники с id-объединениями ищем через `indexById` (`typeById`, `levelById`, `sourceById`): на неизвестный id
  он бросает ошибку. Из кода такой id не пропустит TypeScript, а записи из localStorage проверяются при загрузке
  (`store/persistedState.ts`), поэтому `?.` и `!` в компонентах не нужны. Если страница всё же упадёт,
  `PageErrorBoundary` покажет сообщение вместо белого экрана.
- Шрифты подключаются только из сборки: пакеты `@fontsource` через `src/fonts.css`, внешних хостов вроде Google Fonts
  быть не должно. Набор начертаний в `fonts.css` должен совпадать со шрифтами `--font-*` в `src/index.css`: если
  добавляете новую насыщенность (например, Rubik 400), подключите её файл, иначе браузер подставит системный шрифт.
- Раскладка страниц строится на container queries (`@xl:`, `@4xl:` …): она зависит от ширины области
  контента, а не окна, так что работает и при открытом сайдбаре.
- Демо-коммуникации (`data/timelineEvents.ts`) датируются относительно текущего дня, поэтому таймлайн всегда
  «живой»; их подтверждения доведения генерируются так же. В localStorage сохраняются только коммуникации,
  созданные пользователем, и его подтверждения. Статус коммуникации не хранится — он считается по датам
  и подтверждениям. Демо-пользователь портала — руководитель из пилотной структуры (`data/currentUser.ts`).
  Если меняется формат записей или id справочников, увеличьте `PERSIST_VERSION` и допишите миграцию
  в `store/persistedState.ts` — данные, сохранённые прошлой версией портала, не должны теряться.
- Чисто форматирующие коммиты перечислены в `.git-blame-ignore-revs`; чтобы `git blame` их пропускал локально:
  `git config blame.ignoreRevsFile .git-blame-ignore-revs`.
