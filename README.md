# Каскад — портал каскадирования коммуникаций «Петрович»

Интерактивный прототип портала, на котором руководители заводят «паспорт инфоповода». Тип коммуникации
задаёт тональность и обязательные каналы, срок доведения портал считает сам — всё по Положению
о каскадировании. Пилотная структура — Дирекция по персоналу.

## Стек

React 18 · TypeScript (strict) · Vite · Tailwind CSS (+ container queries) · Zustand · Framer Motion · date-fns · lucide-react

## Команды

Нужен Node.js 20.19+ или 22.13+ (версия для nvm — в `.nvmrc`).

```bash
npm install
npm run dev           # дев-сервер на http://localhost:3000/kaskad-website/
npm run build         # проверка типов + production-сборка в dist/
npm run preview       # локальный просмотр сборки
npm run typecheck     # только проверка типов
npm run lint          # ESLint (typescript-eslint, react-hooks); предупреждения тоже валят проверку
npm run format        # Prettier (+ сортировка классов Tailwind)
npm run format:check  # проверка форматирования без изменений
```

## Структура `src/`

```
pages/            страницы (по одной на раздел меню)
layouts/          каркас страницы (сайдбар, шапка, заголовок) и граница ошибок страницы
components/
  ui/             базовые компоненты: Button, Card, Badge, Chip, Segmented, Stepper…
  navigation/     сайдбар, шапка, хлебные крошки, логотип
  communication/  карточка коммуникации, паспорт (drawer), каналы
  classification/ шаги формы паспорта и модель черновика (passportDraft.ts)
data/             справочники и демо-данные по Положению: типы, уровни, каналы, площадки, приоритеты, кризис, оргструктура
types/            доменные типы
utils/            чистая логика без React: правила каскада, дерево оргструктуры, шкала таймлайна, форматирование
store/            Zustand-стор: созданные пользователем коммуникации и ручные статусы (localStorage, с проверкой при загрузке)
theme/            палитра акцентных цветов и пастельные пары для Tailwind
hooks/            общие хуки
routes.ts         разделы портала: путь, пункт меню, заголовок, иконка
```

## Соглашения

- Цвета из данных — только через `palette` и `alpha()` из `theme/colors.ts`. Цвета для классов Tailwind
  описаны в `tailwind.config.ts`.
- Справочники с id-объединениями ищем через `indexById` (`typeById`, `levelById`, `sourceById`): на неизвестный id
  он бросает ошибку. Из кода такой id не пропустит TypeScript, а записи из localStorage проверяются при загрузке
  (`store/persistedState.ts`), поэтому `?.` и `!` в компонентах не нужны. Если страница всё же упадёт,
  `PageErrorBoundary` покажет сообщение вместо белого экрана.
- Раскладка страниц строится на container queries (`@xl:`, `@4xl:` …): она зависит от ширины области
  контента, а не окна, так что работает и при открытом сайдбаре.
- Демо-коммуникации (`data/timelineEvents.ts`) датируются относительно текущего дня, поэтому таймлайн всегда
  «живой». В localStorage сохраняются только коммуникации, созданные пользователем, и ручные смены статуса.
  Если меняется формат записей или id справочников, увеличьте `PERSIST_VERSION` и допишите миграцию
  в `store/persistedState.ts` — данные, сохранённые прошлой версией портала, не должны теряться.
- Чисто форматирующие коммиты перечислены в `.git-blame-ignore-revs`; чтобы `git blame` их пропускал локально:
  `git config blame.ignoreRevsFile .git-blame-ignore-revs`.
